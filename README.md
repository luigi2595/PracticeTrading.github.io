# ES Practice Lab (React + Vite)

A flight simulator for E-mini S&P 500 futures: a bar-by-bar replay sim with a
TradingView-style order ticket, a live pattern-read trainer (failed
breakdown/breakout, real break, sweep, retest — computed with zero lookahead),
a trade journal with full stats and five mini-charts, and a "Pattern Lab" of
call-the-level drills. This is a full rewrite of an original vanilla-JS
single-file app as an idiomatic React + TypeScript + Vite project, built to
be byte-for-byte faithful to the original's trading math and behavior.

Nothing here is trading advice. The price data is synthetic, and futures
trading can lose more than you deposit.

## Getting started

```bash
npm install
npm run dev
```

Then open the printed local URL. `npm run build` produces a production
build in `dist/`; `npm run preview` serves that build locally.

## Project layout

- `src/lib/` — pure, framework-agnostic logic: the seeded synthetic-bar
  generator, indicators (VWAP/ORB/bands/PD/overnight/session hi-lo, EMA/SMA/
  CMA, buy/sell volume), the live pattern detector, the trading engine
  (fills, commissions, slippage, R-multiples, risk caps, stats), CSV import
  of real bars, Pattern Lab scenario generation, and localStorage
  persistence.
- `src/store/` — a `useReducer`-based store: `state.ts` defines the shape,
  `reducer.ts` is the single pure state-transition function (every user
  action and every replay tick goes through it), and `StoreContext.tsx`
  wires it into React and owns the three effects the original ran as global
  code — the self-rescheduling play loop, debounced autosave, and the
  one-time boot sequence.
- `src/components/` — the UI: `Chart.tsx` (the main canvas chart),
  `OrderTicket.tsx`/`SimSidebar.tsx`/`SimPanel.tsx` (the Replay sim tab),
  `JournalPanel.tsx`/`MiniCharts.tsx` (the Journal tab), `PatternLab.tsx`
  (the drills tab), `Settings.tsx`, `Modals.tsx` (Welcome, MA config, trade
  Replay, closing-bell Debrief), `MobileBar.tsx` (the one-handed phone
  trading bar), and `StatusLayer.tsx` (toast + screen-reader announcer).
- `src/App.tsx` — the shell: header chips, tabs, and wiring the panels/
  modals together.

## Fidelity notes

This is a full, from-scratch rewrite, not a wrapper around the old engine —
but every formula, threshold, and piece of copy was ported directly from the
original source (variable names in comments point back to the original
function it came from). The trading math (fills, commissions, slippage,
R-multiples, position sizing/caps), the pattern detector, and the stats/
debrief logic were additionally checked against the original engine
numerically during development (seeded sessions replayed through both
implementations and diffed) and produced identical results across bars,
indicators, pattern events, order fills, and CSV import.

**Honest limitation:** this was built in a sandboxed environment with no
package registry access, so `npm install` could never actually be run here.
The pure logic in `src/lib/` and `src/store/` was continuously type-checked
with `tsc` throughout development and compiles cleanly. The `.tsx` component
files, however, could **not** be type-checked or run in that environment (no
`@types/react` was available, and nothing could be installed to add it) —
they were written carefully by hand and cross-checked against the original
markup and event-handling code, but you are the first `tsc`/bundler/browser
this code has actually run in. If `npm run build` or `npm run dev` surfaces
a type error or a runtime bug, it's almost certainly in one of the files
under `src/components/` or `src/App.tsx` — that's the place to look first.

## What's intentionally different from a "pure" reducer

Everything in the reducer is a deterministic function of `(state, action)`
except the Pattern Lab's `NEW_SCENARIO` action, which calls scenario
builders that use unseeded `Math.random()` internally. This matches the
original app's own design — the drills were never meant to be reproducible
the way the seeded replay sim is.

A few content-heavy, app-generated (never user-supplied) blocks of rich text
— the Pattern Lab's "why" explanation and its stop-comparison lesson — are
built as HTML-string functions ported near-verbatim from the original and
rendered via `dangerouslySetInnerHTML`, rather than converted into full JSX
trees. This was a deliberate trade-off to preserve exact wording without a
large, low-value conversion effort; it's safe because that HTML is always
generated by the app itself, never from user input.
